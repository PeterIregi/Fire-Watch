# Scaffold

This document is the contract for the repository layout. It records what was
generated by tooling (Vite and uv) and what each owner still needs to create.

The scaffold deliberately does **not** contain empty placeholder modules such
as `pipeline/ingest.py`. Create a file when you start implementing it; do not
commit empty stubs. Empty directories that must survive Git are tracked with
`.gitkeep`.

`data/`, `pipeline/.venv/`, `web/node_modules/`, and build output are ignored
by Git. The exported files under `web/public/data/` are not ignored: the static
site needs them at deploy time.

## How the generated parts were created

Python dependencies and the local environment:

```bash
uv venv pipeline/.venv --python 3.12
uv pip install --python pipeline/.venv/bin/python \
  pandas numpy scipy pyarrow requests python-dotenv matplotlib
uv pip freeze --python pipeline/.venv/bin/python > pipeline/requirements.txt
```

React app and web dependencies:

```bash
npm create vite@latest web -- --template react --no-interactive --no-immediate
cd web
npm install
npm install leaflet leaflet-draw echarts
```

The generated Vite page is a placeholder. Keep the build working, but replace
the demo screen with the FireWatch shell as part of domain C.

## First steps per owner

- **A / B (Python):** activate `pipeline/.venv`, add `pipeline/config.py`, and
  create each pipeline module as it is implemented. Run steps against one year
  before the full range.
- **C (web core):** replace `web/src/App.jsx`, add the data loader in
  `web/src/store/`, and wire the map. Confirm `npm run build` before deploying.
- **D (analytics):** build the calendar, charts, KPIs, anomalies, and export
  modules in their folders against dummy data first.

See [setup.md](setup.md) for environment and data access, and
[task-splitter.md](task-splitter.md) for ownership.
